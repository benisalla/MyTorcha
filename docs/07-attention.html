Chapter 7

Attention and Transformers

An RNN passes information along one step at a time. Attention lets every position look at every other position directly, in one matrix multiply. That's all a Transformer is, plus some careful plumbing.

Scaled dot-product attention

Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V

Each position has a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what do I hand over if chosen?"). Q·Kᵀ scores every query against every key. The softmax turns each row into weights that sum to 1. The output is the weighted average of the values. Dividing by √d keeps the scores from growing with the dimension, which would otherwise push the softmax into a saturated corner with tiny gradients.

import numpy as np
import mytorcha as mt
import mytorcha.functional as F

q = k = v = mt.Tensor(np.eye(3))                 # 3 positions, d = 3
mask = np.triu(np.ones((3, 3), bool), 1)         # True = NOT allowed: the future
print(mask)
print(F.scaled_dot_product_attention(q, k, v, mask).data.round(3))
output
[[False  True  True]
 [False False  True]
 [False False False]]
[[1.    0.    0.   ]
 [0.36  0.64  0.   ]
 [0.264 0.264 0.471]]

Read the output row by row. Position 0 can only see itself. Position 1 sees positions 0 and 1 and prefers itself (its own key matches its query best). Nobody sees the future. That upper-triangular causal mask is what lets a GPT train on every position of a sequence at once without cheating. Masked scores are set to −10⁹ with masked_fill before the softmax, so they get a weight of 0.

Multi-head attention

import mytorcha as mt
from mytorcha import nn

mt.manual_seed(0)
attn = nn.MultiheadAttention(16, num_heads=4)
x = mt.randn(2, 5, 16)                           # (N, T, embed_dim)
print(attn(x, causal=True).shape, attn.num_parameters())
output
(2, 5, 16) 1088

The input is projected to Q, K and V (three Linear(16, 16) layers), and each is split into 4 heads of 4 dimensions. Each head attends independently, which lets one head track "the previous word" while another tracks "the subject of the sentence". The heads are concatenated and mixed by out_proj. That's 4 × (16·16 + 16) = 1,088 parameters.

forward(query, key=None, value=None, mask=None, causal=False): with only query it's self-attention. Pass key/value from another sequence for cross-attention (as in a captioning or translation decoder). mask is True where attention is blocked, for example padding. The output is checked against torch.nn.MultiheadAttention with a causal mask in the tests. One difference: MyTorcha returns only the output, not the attention weights.

The Transformer block

x = x + Attention(LayerNorm(x)) ← talk to the other positions x = x + MLP(LayerNorm(x)) ← think about it, position by position (MLP = Linear → GELU → Linear)
import mytorcha as mt
from mytorcha import nn

mt.manual_seed(0)
x = mt.randn(2, 5, 16)
block = nn.TransformerEncoderLayer(16, nhead=4)  # dim_feedforward defaults to 4·d_model
print(block(x, causal=True).shape, block.num_parameters())
output
(2, 5, 16) 3280

This is the pre-norm layout used by GPT-2 and most modern models: LayerNorm is applied before each sub-layer, and the residual path x + … is left untouched. That path is a gradient highway through the depth of the network, playing the same role the LSTM's cell state plays through time.

Embeddings and positions

Attention by itself is order-blind: shuffle the tokens and each one gets the same output, just shuffled. So we add a position embedding to each token embedding. Both are plain nn.Embedding lookup tables. Their gradient is a scatter-add (np.add.at), so a token that appears three times in a batch collects three gradients.

import numpy as np
from mytorcha import nn

emb = nn.Embedding(20, 16)                       # 20 tokens, 16-d vectors
print(emb(np.array([[3, 1, 4, 1, 5]])).shape)    # integer ids of any shape -> (..., 16)
output
(1, 5, 16)

Example: a tiny GPT

examples/06_tiny_transformer.py builds a two-block, 4-head, 48-dimensional GPT with token embedding + position embedding → blocks with causal=True → LayerNorm → Linear to the vocabulary. It's trained with AdamW on our motto, repeated 40 times, in 32-character windows.

class TinyGPT(nn.Module):
    def __init__(self, vocab, d=48, heads=4, layers=2):
        self.tok, self.pos = nn.Embedding(vocab, d), nn.Embedding(T, d)
        self.blocks = [nn.TransformerEncoderLayer(d, heads) for _ in range(layers)]
        self.ln, self.head = nn.LayerNorm(d), nn.Linear(d, vocab)

    def forward(self, ids):
        x = self.tok(ids) + self.pos(np.arange(ids.shape[1]))
        for block in self.blocks:
            x = block(x, causal=True)    # each position may only look at the past
        return self.head(self.ln(x))
output
59,825 parameters
step   0 | loss 3.068
step  50 | loss 0.600
step 100 | loss 0.095
step 150 | loss 0.063
step 200 | loss 0.059
greedy sample: the deal is in the details. i do not learn things until i build them. the deal is in

The loss falls from 3.07 to 0.059 in 200 steps, and greedy decoding reproduces the training sentence, then loops back to its beginning. Like the LSTM, it has memorised a tiny text. Unlike the LSTM, every position of a window is trained in parallel: there's no hidden state to wait for, step after step.

Why the loss doesn't reach 0. The first positions of each window have almost no context. After a lone t the next character could be h (the, things, them), a (details), i (until) or a space (not), so those predictions stay uncertain however long you train.

Where to go from here

  • Read src/mytorcha/tensor.py top to bottom. It's under 400 lines, and it's the whole engine.
  • Add an op. Write forward and grad_fn, then prove it with gradcheck. A good first one is Tensor.std, or sin/cos.
  • Swap the GPT's data for a real text file and train it longer. It will stop memorising and start inventing.
  • Then open PyTorch's documentation. Every page will read like a description of something you've already built.

Try it

1. Without the causal mask, what would the tiny GPT learn during training?

To copy: the answer for position t is the input at position t + 1, which it could simply look at. The training loss would drop to near zero, and generation would be garbage, because at generation time the future doesn't exist yet.

2. Why √d and not d?

If q and k have independent unit-variance entries, q·k is a sum of d terms with variance d, so its standard deviation is √d. Dividing by √d brings the scores back to unit scale.

3. Remove the position embedding from TinyGPT (x = self.tok(ids)). Does it still learn the sentence?

Yes, and that surprised us too. We ran it: loss 3.036 → 0.060 at step 200 (vs 0.059 with positions), with the same greedy sample. The causal mask leaks order on its own. Position t averages over exactly t + 1 tokens, so the model can work out where it is. Decoder-only models without position embeddings ("NoPE") are a known research result. Without the causal mask, though, attention really is order-blind. A good lesson in testing the textbook claim instead of repeating it.
