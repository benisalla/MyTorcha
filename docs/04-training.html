Chapter 4

Losses, optimizers and the training loop

A loss turns "how wrong" into one number. backward() says which way is downhill. An optimizer decides how big a step to take. Repeat a few thousand times and call it learning.

The five-line training loop

Every training loop in the world, PyTorch included, is these five lines inside two for loops:

import mytorcha as mt
from mytorcha import nn, optim

mt.manual_seed(0)
X, y = mt.datasets.make_moons(n=400, noise=0.15)
loader = mt.DataLoader(mt.TensorDataset(X, y), batch_size=32, shuffle=True)

model = nn.Sequential(nn.Linear(2, 32), nn.Tanh(), nn.Linear(32, 2))
loss_fn = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=0.1, momentum=0.9)

for epoch in range(20):
    for xb, yb in loader:
        loss = loss_fn(model(xb), yb)   # 1. forward
        optimizer.zero_grad()           # 2. clear old gradients
        loss.backward()                 # 3. backward
        optimizer.step()                # 4. update
    if epoch % 5 == 4:                  # 5. look at it, always look at it
        print(f"epoch {epoch + 1:2d} | last batch loss {loss.item():.4f}")

with mt.no_grad():
    acc = (model(mt.Tensor(X)).data.argmax(-1) == y).mean()
print(f"train accuracy {acc:.1%}")
output
epoch  5 | last batch loss 0.1457
epoch 10 | last batch loss 0.0743
epoch 15 | last batch loss 0.0598
epoch 20 | last batch loss 0.0200
train accuracy 98.8%

Losses

Every loss exists as a function in mytorcha.functional and as a module in mytorcha.nn. All of them take reduction="mean" | "sum" | "none".

Cross-entropy is the one you'll use most, so here it is up close:

import numpy as np
import mytorcha as mt
import mytorcha.functional as F

logits = mt.Tensor([[2.0, 0.5, -1.0], [0.1, 0.2, 3.0]], requires_grad=True)
target = np.array([0, 2])
loss = F.cross_entropy(logits, target)
loss.backward()
print(round(loss.item(), 4))
print(np.round(logits.grad, 4))
output
0.1755
[[-0.1072  0.0876  0.0196]
 [ 0.0247  0.0272 -0.0519]]

The gradient is (softmax(logits) − one_hot(target)) / N: push the right class up and the others down, in proportion to how confident the model was. Internally it uses a stable log_softmax that subtracts the max before exponentiating, so logits of 1000 don't overflow. That was bug #8 in v1.

One deliberate difference from PyTorch. MyTorcha puts the classes on the last axis: logits are (..., C) and targets are (...). PyTorch wants classes on axis 1. The payoff is that a sequence model's (N, T, C) output goes straight into the loss without a transpose:

import numpy as np
import mytorcha as mt
from mytorcha import nn

seq = mt.randn(4, 7, 50)                                       # (batch, time, vocab)
labels = np.random.default_rng(0).integers(0, 50, (4, 7))
print(nn.CrossEntropyLoss()(seq, labels).shape)                # a scalar
output

Optimizers

An optimizer gets the parameter list once, then step() updates each parameter from its .grad. Every optimizer keeps its own state per parameter: a momentum buffer shaped like that weight. That sounds obvious, but v1 got it wrong (bug #4). It had one scalar momentum shared by all weights, so each weight's update was polluted by every other weight's gradients.

import numpy as np
from mytorcha import nn, optim

a, b = nn.Parameter([1.0]), nn.Parameter([1.0])
opt = optim.Adam([a, b], lr=0.1)
a.grad = np.array([1.0], np.float32)      # a should go down...
b.grad = np.array([-1.0], np.float32)     # ...and b should go up
opt.step()
print(a.data, b.data, sorted(opt.state[0]))
output
[0.9] [1.1] ['m', 'v']

Below, g is the gradient, w the weight and η the learning rate. All formulas follow the PyTorch documentation, and the tests check them against torch.optim to within 10⁻⁶.

OptimizerUpdate (per element)When to use it
SGD(lr, momentum, nesterov, weight_decay)v = μv + g; w −= η·v (Nesterov: w −= η(g + μv))the baseline; with momentum, still a top choice for CNNs
Adagrad(lr)s += g²; w −= η·g/(√s + ε)sparse features; the step size only ever shrinks
RMSprop(lr, alpha, momentum, centered)s = αs + (1−α)g²; w −= η·g/(√s + ε)RNNs, non-stationary problems
Adadelta(lr=1.0, rho)RMSprop with a step scaled by the RMS of past updateswhen you don't want to tune lr
Adam(lr, betas, amsgrad)m = β₁m + (1−β₁)g; v = β₂v + (1−β₂)g²; w −= η·m̂/(√v̂ + ε) with bias-corrected m̂, v̂the default for almost everything
AdamW(lr, weight_decay=0.01)Adam, plus w −= η·λ·w applied directly (decoupled)Transformers, and any time you want weight decay with Adam
Adamax(lr)Adam with u = max(β₂u, |g|) instead of √va robust Adam variant
Lion(lr, betas)w −= η·sign(β₁m + (1−β₁)g)modern and memory-light; use about 10× smaller lr than Adam

Why bias correction? Adam's averages m and v start at zero, so early on they underestimate the true moments. Dividing by 1 − βᵗ fixes that. v1 had no bias correction and unusual betas (0.99, 0.994). The standard (0.9, 0.999) are the defaults now.

The optimizer race

Four optimizers start at the same point on a 2-D loss surface. The "long valley" is steep across and almost flat along its length. Plain SGD has to use a small step to avoid bouncing across the steep direction, so it crawls along the flat one. Momentum builds up speed along the valley. RMSprop and Adam rescale each coordinate by its own gradient size. The slider multiplies every optimizer's learning rate. Push it up and watch who diverges first.

    Each optimizer has its own base learning rate, because they work on different scales (Adam's lr is roughly a step size in weight units, SGD's multiplies the raw gradient). The banana gets smaller rates than the valley because it is far more curved: on the banana SGD needs lr ≈ 0.004 where the valley allows 0.12.     Learning-rate schedules

    A scheduler changes optimizer.lr each time you call scheduler.step(), usually once per epoch:

    from mytorcha import nn, optim

def lrs(make, n=6):
    opt = optim.SGD([nn.Parameter([0.0])], lr=1.0)
    s = make(opt)
    return [round(s.step(), 3) for _ in range(n)]

print("StepLR       ", lrs(lambda o: optim.StepLR(o, step_size=2, gamma=0.5)))
print("ExponentialLR", lrs(lambda o: optim.ExponentialLR(o, gamma=0.8)))
print("Cosine       ", lrs(lambda o: optim.CosineAnnealingLR(o, T_max=6)))
print("Warm-up      ", lrs(lambda o: optim.LambdaLR(o, lambda e: min(1.0, (e + 1) / 4))))
    output

ExponentialLR [0.8, 0.64, 0.512, 0.41, 0.328, 0.262]
Cosine        [0.933, 0.75, 0.5, 0.25, 0.067, 0.0]
Warm-up       [0.5, 0.75, 1.0, 1.0, 1.0, 1.0]

    Cosine annealing is a good default. A linear warm-up (with LambdaLR) is standard for Transformers, because Adam's early steps are unreliable until its moment estimates have warmed up.

    Gradient clipping

    import numpy as np
from mytorcha import nn, optim

w = nn.Parameter([0.0, 0.0])
w.grad = np.array([30.0, 40.0], dtype=np.float32)
print(optim.clip_grad_norm_([w], max_norm=1.0), w.grad)
    output
    50.0 [0.59999996 0.79999995]

    clip_grad_norm_ treats all gradients as one long vector. If its length is above max_norm, every gradient is scaled down by the same factor, so the direction is kept and only the step is shortened. It returns the norm before clipping, which is worth logging. Recurrent networks need this (chapter 6).

    Data: Dataset, TensorDataset, DataLoader

    • TensorDataset(X, y) wraps arrays that share their first dimension.
    • DataLoader(ds, batch_size=32, shuffle=True, drop_last=False) yields tuples of Tensors. Float arrays become float32, and integer labels stay integers. With shuffle=True it reshuffles every epoch using the global seed.
    • For anything custom, subclass Dataset with __len__ and __getitem__(i) returning a tuple of arrays. The loader stacks them.
    class Squares(mt.Dataset):
    def __len__(self):
        return 100
    def __getitem__(self, i):
        x = np.array([i / 100], dtype=np.float32)
        return x, x ** 2

    Or let Trainer write the loop

    mt.Trainer is the five-line loop plus evaluation, a scheduler, optional clipping and a history list. It's about 75 lines in src/mytorcha/trainer.py, so do read it.

    import mytorcha as mt
from mytorcha import nn, optim

mt.manual_seed(0)
Xtr, ytr = mt.datasets.make_moons(n=400, noise=0.15)
Xva, yva = mt.datasets.make_moons(n=200, noise=0.15)
model = nn.Sequential(nn.Linear(2, 32), nn.Tanh(), nn.Linear(32, 2))
opt = optim.AdamW(model.parameters(), lr=1e-2, weight_decay=1e-4)
trainer = mt.Trainer(model, nn.CrossEntropyLoss(), opt, scheduler=optim.CosineAnnealingLR(opt, T_max=5))
history = trainer.fit(mt.DataLoader(mt.TensorDataset(Xtr, ytr), batch_size=32, shuffle=True), epochs=5,
                      val_loader=mt.DataLoader(mt.TensorDataset(Xva, yva), batch_size=200))
print(trainer.predict(Xva[:3]).argmax(-1), yva[:3])

    Try it

    1. In the five-line loop, swap zero_grad() and backward(). What happens?

    You compute the gradients and then immediately erase them, so step() finds grad = None and does nothing. The loss never moves. Order matters: zero, backward, step.

    2. Logits are [0, 0, 0] and the target is class 1. What is the cross-entropy?

    log 3 ≈ 1.0986. Equal logits mean a uniform 1/3 for each class, and −log(1/3) = log 3. Remember it: an untrained C-class model starts at a loss of about log C. The tiny GPT in chapter 7 (17 characters) starts at 3.07, a little above log 17 ≈ 2.83, because random weights are not perfectly uniform.

    3. In the race, why can't you just raise SGD's learning rate until it's as fast as Adam?

    SGD has one learning rate for every direction. The steep direction (curvature 4) diverges once lr > 0.5, while the flat one (curvature 0.1) would want lr ≈ 10. Adam and RMSprop divide by each coordinate's own gradient scale, which acts like a per-direction learning rate.
