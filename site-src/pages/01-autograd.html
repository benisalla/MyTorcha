Chapter 1

Autograd with single numbers

Before tensors, before layers, there is one idea: a number that remembers how it was made. Get this chapter and the rest of the framework is just bookkeeping.

A number with a memory

A Node from mytorcha.scalar stores four things:

  • data: its value;
  • grad: how much the final output changes if you nudge this node (filled in by backward());
  • _prev: the nodes it was computed from;
  • _backward: a tiny function that pushes grad into those inputs.

Every arithmetic operation creates a new node and wires it to its inputs. So writing an ordinary formula quietly builds a directed acyclic graph (DAG) of the computation:

```python from mytorcha.scalar import Node x = Node(2.0) y = x * x + x.log() y.backward() print(y.data, x.grad) ``` ```output 4.693147180559945 4.5 ```

Check it by hand: y = x² + log x, so dy/dx = 2x + 1/x = 4 + 0.5 = 4.5. The framework did the calculus for us, by following the graph.

The chain rule, one node at a time

Each operation only knows its local derivative. Multiplication knows that d(a·b)/da = b. Log knows that d(log x)/dx = 1/x. The chain rule says the gradient of the final output with respect to any node is:

```math node.grad = Σ over every use of the node: (local derivative) × (grad of the result) ```

Here's multiplication from src/mytorcha/scalar.py. The whole engine is variations on this:

```python-norun def __mul__(self, other): other = other if isinstance(other, Node) else Node(other) out = Node(self.data * other.data, (self, other), "*") def _backward(): self.grad += other.data * out.grad # d(a·b)/da = b other.grad += self.data * out.grad # d(a·b)/db = a out._backward = _backward return out ```

Note the +=. In x * x, the node x is used twice, so it collects gradient twice: 2 + 2 = 4. That's the "sum over every use" in the formula. With = instead of +=, any reused value would get half its gradient.

Order matters: the topological sort

A node can only push its gradient back once it has received all of its own gradient. So backward() first lists the nodes so that every node comes after its inputs (a topological order), sets the output's grad to 1, and walks that list in reverse:

```python from mytorcha.scalar import Node x = Node(2.0, label="x") a = x * x b = x.log() y = a + b print([n._op or n.label for n in y.topo()]) y.backward() print(a.grad, b.grad, x.grad) ``` ```output ['x', 'log', '*', '+'] 1.0 1.0 4.5 ```

Inputs come first and the output last. Walking in reverse, + hands 1.0 to both a and b, then * and log each pour their share into x: 2·2·1 + (1/2)·1 = 4.5.

Why iterative? Version 1 sorted the graph with a recursive function. One neuron with 784 inputs is already a chain of about 785 additions, and a couple of layers deeper you hit Python's recursion limit (1000) and crash. The new topo() uses an explicit stack, and a test backpropagates through a 5,000-node chain to keep it that way.

Two nodes with the same value are still two nodes

Version 1 overrode __eq__ and __hash__ to compare nodes by value. That sounds harmless until backward() keeps a visited set:

```python from mytorcha.scalar import Node a, b = Node(3.0), Node(3.0) print(a == b, len({a, b})) ``` ```output False 2 ```

In v1 this printed True 1: the two weights collapsed into one set entry, the second was treated as already visited, and its part of the graph never got a gradient. Worse, the hash also depended on the gradient, which changes during backprop. Now nodes use plain identity: same object means same node, and that's the only rule.

Play with a graph

This is a single neuron with one input. Its output a = tanh(w·x + b) is compared with a target t, and the loss is L = (a − t)². Move the sliders: each box shows its value and its gradient dL/d(node), computed in your browser by the same forward/backward recipe. Then press Take a gradient step, which runs w -= lr * w.grad and b -= lr * b.grad, and watch the loss shrink.

Neuron: L = (tanh(w·x + b) − t)²

This interactive graph needs JavaScript. The text above explains the same computation.

Things to notice while you play:

  • The grad of w is always x times the grad of w·x. Set x = 0 and w stops learning. That's why inputs are normalised.
  • Push b to ±3 and tanh saturates: 1 − a² ≈ 0, so every gradient behind tanh goes to zero. That's a "dead" neuron, and it's why weight init matters (chapter 3).
  • With lr = 2 the steps overshoot and bounce. Too large a learning rate is not "faster". It's wrong.

Train a network with nothing but Nodes

mytorcha.scalar also has the original Neuron, Layer and MLP. One fix matters a lot: the last layer is now linear. v1 applied ReLU to the output, which clips negative scores to zero before the loss even sees them. XOR is the classic test, because no single line separates it:

```python import random from mytorcha.scalar import MLP, sum_nodes random.seed(0) X, Y = [[0, 0], [0, 1], [1, 0], [1, 1]], [0, 1, 1, 0] model = MLP(2, [8], 1, act="tanh") print("parameters:", len(model.parameters())) for step in range(301): loss = sum_nodes([(model(x)[0] - y) ** 2 for x, y in zip(X, Y)]) model.zero_grad() # gradients accumulate (+=), so clear them first loss.backward() for p in model.parameters(): p.data -= 0.05 * p.grad if step % 50 == 0: print(f"step {step:3d} | loss {loss.data:.4f}") print("predictions:", [round(model(x)[0].data, 3) for x in X], "targets:", Y) print("graph size for one forward pass:", len(model(X[0])[0].topo()), "nodes") ``` ```output parameters: 33 step 0 | loss 1.7710 step 50 | loss 0.7410 step 100 | loss 0.2354 step 150 | loss 0.0160 step 200 | loss 0.0005 step 250 | loss 0.0000 step 300 | loss 0.0000 predictions: [0.0, 1.0, 1.0, 0.0] targets: [0, 1, 1, 0] graph size for one forward pass: 106 nodes ```

This is examples/01_xor_scalar.py. Thirty-three parameters make a 106-node graph per sample. Scale that to a 784-pixel image and one 10-class layer makes 31,427 nodes per image. The idea is perfect, the bookkeeping is too slow, and that's exactly why chapter 2 exists.

See the graph. With pip install graphviz (and the Graphviz binaries), mytorcha.scalar.draw(loss) returns a picture of every node with its value and gradient. It's the closest thing to an X-ray of backprop.

Try it

Predict first, then open the answer. Run it if you don't believe it (you shouldn't, that's the spirit).

1. x = Node(3.0); (x * x * x).backward(). What is x.grad?

27.0. d(x³)/dx = 3x² = 27. The graph is two multiplications. x appears three times, and the += collects all three contributions.

2. x = Node(-1.0); (x.relu() * 5).backward(). What is x.grad?

0.0. ReLU's derivative is 0 for negative inputs, so the 5 never reaches x. A neuron stuck on the negative side gets no gradient at all: the "dying ReLU".

3. x = Node(0.5); (x * 2).tanh().backward(). Is x.grad bigger or smaller than 2?

Smaller: 0.8399. It equals 2 · (1 − tanh(1)²). The chain rule multiplies the local derivatives, and tanh's is always ≤ 1.

4. Why does backward() set the output's grad to 1 and not 0?

Because the output's gradient with respect to itself is dy/dy = 1. Every other gradient is that 1 multiplied by local derivatives along the way. Start from 0 and everything stays 0. (In v1 the losses had to set it by hand, and cross-entropy got around it with a manual hack on the logits.)
