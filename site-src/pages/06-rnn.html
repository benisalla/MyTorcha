Recurrent networks: RNN, LSTM, GRU

A recurrent network reads a sequence one step at a time and carries a memory, the hidden state, from each step to the next. It's one small cell, applied T times.

Shapes first

MyTorcha's recurrent layers are batch-first: input (N, T, input_size), output (N, T, hidden·directions). (PyTorch defaults to time-first. We picked the version that's harder to get wrong.)

```python import mytorcha as mt from mytorcha import nn mt.manual_seed(0) x = mt.randn(4, 7, 10) # (batch N, time T, features) out, h = nn.RNN(10, 32)(x) print(out.shape, h.shape) out, (h, c) = nn.LSTM(10, 32, num_layers=2, bidirectional=True)(x) print(out.shape, h.shape, c.shape) print(nn.GRU(10, 32)(x)[0].shape) ``` ```output (4, 7, 32) (1, 4, 32) (4, 7, 64) (4, 4, 32) (4, 4, 32) (4, 7, 32) ```
  • out is the top layer's hidden state at every time step: use it for per-step predictions.
  • h (and c for the LSTM) is the final state of every layer and direction, with shape (num_layers·dirs, N, H). That's 2 layers × 2 directions = 4 above. Use it to classify a whole sequence, or pass it back in to continue one.
  • bidirectional=True runs a second cell backwards in time and concatenates both, which is why it's 64 = 2×32 features.

The three cells

All three cells use PyTorch's weight names (weight_ih, weight_hh, bias_ih, bias_hh) and gate order, and the tests copy weights into torch.nn.LSTM/GRU/RNN and match outputs and gradients to 10⁻¹⁰ (2 layers, bidirectional).

RNN (Elman)

```math h' = tanh(x·W_ihᵀ + b_ih + h·W_hhᵀ + b_hh) ```

It's simple, and it forgets fast. Backpropagating through T steps multiplies T Jacobians together, so gradients shrink (vanish) or blow up (explode) exponentially with T.

LSTM: gates i, f, g, o

```math i = σ(·) f = σ(·) g = tanh(·) o = σ(·) ← one matmul gives all four (weight_ih is 4H × input) c' = f·c + i·g ← the cell state is only scaled and added to h' = o·tanh(c') ```

The trick is c. It's updated by gated addition rather than squashed through a matrix every step. When the forget gate f ≈ 1, the gradient flows back along c almost unchanged: a gradient highway through time. That's why LSTMs remember over hundreds of steps where plain RNNs give up after a dozen. Here's the code from src/mytorcha/nn/recurrent.py:

```python-norun def step(self, xp, state): # xp = x @ W_ihᵀ + b_ih, precomputed for all steps h, c = state z = xp + self.project_hidden(h) H = self.hidden_size i, f = F.sigmoid(z[:, :H]), F.sigmoid(z[:, H : 2 * H]) g, o = F.tanh(z[:, 2 * H : 3 * H]), F.sigmoid(z[:, 3 * H :]) c = f * c + i * g return o * F.tanh(c), c ```

GRU: gates r, z, n

```math r = σ(W_ir·x + W_hr·h) reset gate z = σ(W_iz·x + W_hz·h) update gate n = tanh(W_in·x + r·(W_hn·h)) h' = (1 − z)·n + z·h ```

A GRU is an LSTM with the cell state folded into h, and three gates instead of four. It usually performs about the same as an LSTM, with fewer parameters.

Under the hood: backpropagation through time

There is no special "BPTT algorithm" in MyTorcha. LSTM.forward is a Python for loop that calls the cell T times. That builds one long graph, T copies of the cell sharing the same weights, and the ordinary backward() walks it in reverse. Because the weights are shared, each one collects a gradient from every time step: += again, just like x * x in chapter 1. One optimisation: x @ W_ihᵀ doesn't depend on h, so it's computed for all T steps in a single matmul before the loop. Only h @ W_hhᵀ is truly sequential.

You can also drive a cell yourself:

```python import mytorcha as mt from mytorcha import nn x = mt.randn(4, 7, 10) cell = nn.LSTMCell(10, 32) state = None # None = start from zeros for t in range(7): state = cell(x[:, t], state) # one time step: (N, 10) -> (h, c) h, c = state print(h.shape, c.shape) ``` ```output (4, 32) (4, 32) ```

Exploding gradients and truncated BPTT

Two habits keep recurrent training stable:

  1. Clip the gradient norm every step: optim.clip_grad_norm_(model.parameters(), 1.0), or Trainer(..., clip_grad=1.0). One bad batch can otherwise produce a gradient a million times too large and wipe out the weights.
  2. Truncate long sequences. Feed the sequence in chunks, keep the hidden state's value between chunks, but cut the graph with nn.detach_state so backward() only goes back one chunk:
```python import mytorcha as mt from mytorcha import nn, optim lstm, head = nn.LSTM(10, 32), nn.Linear(32, 1) opt = optim.Adam(lstm.parameters() + head.parameters(), lr=1e-3) state = None for chunk in range(3): # e.g. three slices of one long stream xb, yb = mt.randn(4, 5, 10), mt.randn(4, 5, 1) out, state = lstm(xb, state) # continue from the previous chunk's memory loss = nn.MSELoss()(head(out), yb) opt.zero_grad() loss.backward() # ...but only backprop through this chunk optim.clip_grad_norm_(opt.params, 1.0) opt.step() state = nn.detach_state(state) # keep the values, drop the history print(state[0].requires_grad, state[0].shape) ``` ```output False (1, 4, 32) ```

Example: forecasting a sine wave

examples/04_sine_rnn_lstm_gru.py predicts the next value of noisy sine waves (256 sequences of 30 steps) with each cell type: 32 hidden units, Adam at lr 10⁻², clipping at 1.0, 15 epochs. Baseline first: just predict "the next value equals the current one".

```python-norun class Forecaster(nn.Module): def __init__(self, cell): self.rnn = cell(1, 32) # (N, T, 1) -> (N, T, 32) self.head = nn.Linear(32, 1) # one prediction per time step def forward(self, x): out, _ = self.rnn(x) return self.head(out) ``` ```output baseline (copy last value) MSE: 0.03605 RNN params 1153 | final MSE 0.00835 | 1.1s LSTM params 4513 | final MSE 0.00504 | 3.3s GRU params 3393 | final MSE 0.00495 | 5.6s ```

All three beat the baseline by 4–7×. On sequences this short the plain RNN does fine. The gates pay off as sequences get longer.

Example: a character-level LSTM that writes

examples/05_char_lstm.py is a tiny homage to Karpathy's "The Unreasonable Effectiveness of Recurrent Neural Networks". It uses an Embedding for characters, an LSTM with 128 units, and a Linear layer back to the 25-character vocabulary: 86,969 parameters in total. It's trained on a few sentences about this very framework, in 48-character windows. Because CrossEntropyLoss takes classes on the last axis, the (N, T, vocab) logits go straight in.

```python-norun class CharLSTM(nn.Module): def __init__(self, vocab, emb=32, hidden=128): self.emb = nn.Embedding(vocab, emb) self.lstm = nn.LSTM(emb, hidden) self.head = nn.Linear(hidden, vocab) def forward(self, ids, state=None): out, state = self.lstm(self.emb(ids), state) return self.head(out), state ```

To generate text, it feeds one character at a time and carries the state forward, sampling from softmax(logits / temperature). Here's what it wrote during training:

```output step 0 | loss 3.230 | 'the dbveclgk stmap,sed d ahylb.kdy.a,,p wa.mbcsiswrcrcis.zdalga' step 100 | loss 0.160 | 'the chain rule walks that memory backwards. every weight gets it' step 200 | loss 0.081 | 'the details. i do not learn things until i build them. a tensor ' step 300 | loss 0.071 | 'the details. i do not learn things until i build them. a tensor ' final sample: every weight gets its own gradient, every optimizer keeps its own state. the deal is in the details. i do not learn things unt ```

It goes from keyboard-mashing to quoting its training text, and it even picked up our motto. To be clear, this is memorisation of a tiny text, not creativity. Feed it a bigger corpus and wait longer for the creative part, Inshallah.

Try it

1. nn.LSTM(10, 32): what's the shape of cells[0].weight_ih, and why?

(128, 10). Four gates × 32 hidden units, stacked so one matmul computes them all. A GRU has 3·32 = 96 rows, and an RNN has 32.

2. An LSTM's forget gate outputs f ≈ 0 at some step. What happens to the gradient flowing back along c past that step?

It's cut to (almost) zero: c' = f·c + i·g, so dc'/dc = f ≈ 0. The LSTM chose to forget, and the gradient respects that. With f ≈ 1 it passes through almost untouched.

3. You forget detach_state in the chunked loop. What goes wrong?

The graph keeps growing chunk after chunk, so memory and backward time grow without limit. Worse, the second backward() re-traverses earlier chunks whose gradients were already applied.
