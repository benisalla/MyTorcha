MyTorcha 0.2

A deep learning framework you can read in an afternoon

MyTorcha is a small framework, written from scratch in Python and NumPy, that trains real neural networks: MLPs, CNNs, RNNs, LSTMs, GRUs and Transformers. Every gradient is computed by code you can open and read. No magic, no C++ kernels hiding in the basement.

“The deal is in the details.” PyTorch hides the details so you can ship. MyTorcha shows them so you can understand. Then you go back to PyTorch, and it suddenly makes sense.

It started as a baby framework that hopes to grow into something bigger, Inshallah. Version 0.2 is the growth spurt. It has two engines that share one idea:

  • mytorcha.scalar: every number is its own node in a graph. It's slow, but you can watch backpropagation happen one multiplication at a time. This is the original MyTorcha, bug-fixed.
  • mytorcha.Tensor: the same chain rule, but every node holds a whole NumPy array. Fast enough to train a CNN on handwritten digits on a laptop CPU.

The only runtime dependency is NumPy. PyTorch appears in exactly one place: the test suite, which checks that our numbers match theirs.

Install

```bash git clone https://github.com/benisalla/MyTorcha cd MyTorcha pip install -e . # the framework (needs only NumPy) pip install -e '.[dev]' # + pytest and ruff, if you want to run the tests pytest # 160 tests: gradient checks and PyTorch parity ```

Python 3.10 or newer. If you also want the PyTorch comparison tests, install torch too (pip install -e '.[parity]'). Without it, those tests are skipped politely.

MyTorcha in 30 seconds

Three spirals of points, one per class. No straight line can separate them, so a linear model should fail and a small MLP should not. Baseline first, then the idea:

```python import mytorcha as mt from mytorcha import nn, optim mt.manual_seed(0) X, y = mt.datasets.make_spirals(n_per_class=100, n_classes=3) loader = mt.DataLoader(mt.TensorDataset(X, y), batch_size=32, shuffle=True) full = mt.DataLoader(mt.TensorDataset(X, y), batch_size=300) def train(model): trainer = mt.Trainer(model, nn.CrossEntropyLoss(), optim.Adam(model.parameters(), lr=1e-2)) trainer.fit(loader, epochs=200, verbose=False) return trainer.evaluate(full)["acc"] linear = nn.Linear(2, 3) mlp = nn.Sequential(nn.Linear(2, 64), nn.ReLU(), nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, 3)) print(f"linear accuracy: {train(linear):.1%}") print(f"MLP accuracy: {train(mlp):.1%}") ``` ```output linear accuracy: 53.7% MLP accuracy: 99.3% ```

If that code looks exactly like PyTorch, that's on purpose. The API is borrowed, and the insides are home-made.

The chapters

Each chapter builds on the previous one. Every snippet runs, every output on these pages was produced by actually running it, and each chapter ends with "try it" questions. Predict the answer before you open it. That's where the learning happens.

  1. Autograd with single numbers: a computation graph by hand, the chain rule, and an interactive graph you can poke.
  2. Tensors: the same idea for whole arrays, broadcasting, and the gradient checker that keeps us honest.
  3. Modules and layers: Module, Parameter, Sequential, saving and loading, weight init.
  4. Losses, optimizers, training: all 10 losses, all 8 optimizers, schedules, clipping, and an optimizer race.
  5. Convolutional networks: Conv2d, pooling, BatchNorm, im2col, plus a convolution visualiser.
  6. RNN, LSTM, GRU: recurrence, gates, backpropagation through time, and a text-writing LSTM.
  7. Attention and Transformers: multi-head attention, causal masks, and a tiny GPT.

And the API reference, with every public function and its exact signature.

What version 1 got wrong

The first MyTorcha had the right idea and several bugs. Some of them meant it couldn't learn properly. Every row below was reproduced before it was fixed, and each fix now has a test so it can't come back.

#WhereBugEffect
1Node.logbackward used 1/log(x) instead of 1/xd/dx log(x) at x=2 gave 1.4427 instead of 0.5. Every loss using log was wrong.
2Node.elubackward used x·eˣ instead of α·eˣat x=−1 it gave −0.3679 instead of +0.3679: the wrong sign.
3Node.__eq__ / __hash__nodes compared by value, and the hash changed as the gradient changedtwo different weights holding 3.0 collapsed into one set entry, so backward() could skip whole subgraphs
4Stateful optimizersone scalar momentum / cache shared by all parametersAdam, RMSProp, Adagrad and momentum mixed every weight's history together
5gradient_descentdefined as opt_function(model), called as opt_function()crashed with a TypeError (after printing "we are in sgd")
6SimpleFCReLU also applied to the output layernegative logits were clipped to 0 before the softmax
7main.pytrain/validation split swappedtrained on 10% of the data and "validated" on 90%
8tanh, sigmoid, softplus, softmaxraw expoverflow on large inputs
9backward()recursive topological sorthits Python's recursion limit: one 784-input neuron is already a chain ~785 additions deep
10READMErequirements.txt didn't exist, and the example used the wrong argument namesthe quick start didn't run

The old code still lives in legacy/, for archaeology and humility.
