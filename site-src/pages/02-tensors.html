Chapter 2

Tensors

Same chain rule, bigger boxes. A Tensor is a node whose value is a whole NumPy array, so one matrix multiply replaces thousands of scalar nodes.

Your first Tensor

```python import mytorcha as mt x = mt.Tensor([[1.0, 2.0], [3.0, 4.0]], requires_grad=True) y = (x * x).sum() y.backward() print(y) print(x.grad) ``` ```output Tensor(30., requires_grad=True) [[2. 4.] [6. 8.]] ```

Three things to notice:

  • requires_grad=True marks a tensor whose gradient we want: weights, or an input you want to explain. Without it, no graph is recorded through that tensor. That's cheaper, and it's the default for data.
  • backward() without arguments only works on a scalar (a single number, usually the loss), because it starts from dy/dy = 1.
  • x.grad is a plain NumPy array with the same shape as x: here 2x, element by element.

What one operation looks like

Every op in src/mytorcha/tensor.py computes its output and stores a _grad_fn. Given the gradient g arriving at the output, _grad_fn returns one gradient per input. Here's matrix multiplication, the workhorse of deep learning:

```python-norun def __matmul__(self, other): a, b = self.data, other.data def grad_fn(g): # g = dL/dC, where C = A @ B return g @ b.T, a.T @ g # dL/dA = g·Bᵀ, dL/dB = Aᵀ·g return Tensor._make(a @ b, (self, other), grad_fn, "@") ```

(The real version also handles vectors and batches of matrices.) Then backward() does exactly what the scalar engine did: a topological sort, then reverse order, adding each returned gradient into the input's .grad. The difference from chapter 1 is that the ops return gradients instead of mutating their parents. That's cleaner, and it lets the engine handle broadcasting in a single place.

Shape rule. A gradient always has the same shape as the thing it's the gradient of. If you ever wonder whether it should be g @ b.T or b.T @ g, write down the shapes. Only one order fits.

Broadcasting and _unbroadcast

NumPy lets you add a bias of shape (3,) to a batch of shape (4, 3): the bias is silently reused for every row. Reused means "used four times", and the chain rule says a value used four times collects four gradients:

```python import numpy as np import mytorcha as mt x = mt.Tensor(np.ones((4, 3)), requires_grad=True) b = mt.Tensor(np.zeros(3), requires_grad=True) (x + b).sum().backward() print(b.grad) ``` ```output [4. 4. 4.] ```

The engine does this in one helper, _unbroadcast(grad, shape). It sums the gradient over every axis that broadcasting stretched, until it's back to the input's shape. Because the engine calls it for every op, no individual op has to think about broadcasting.

Gradients accumulate, so zero them

```python import mytorcha as mt a = mt.Tensor([1.0, 2.0], requires_grad=True) (a * 3).sum().backward() (a * 3).sum().backward() print(a.grad) a.zero_grad() print(a.grad) ``` ```output [6. 6.] None ```

Calling backward() twice adds. That's a feature: it's how one node used in two places gets both contributions, and it lets you accumulate gradients over several small batches. But in a training loop you must clear them every step: optimizer.zero_grad() or model.zero_grad(). Forgetting this is the most common bug in all of deep learning. It's not just a MyTorcha thing; PyTorch users do it too, daily.

Turning the graph off: no_grad

```python import mytorcha as mt a = mt.Tensor([1.0, 2.0], requires_grad=True) with mt.no_grad(): z = a * 2 print(z.requires_grad) ``` ```output False ```

Inside no_grad() nothing is recorded, so there's no memory for a graph and no time spent wiring it. Use it for evaluation and inference. Trainer.evaluate and Trainer.predict already do.

dtypes: float32 by default

```python import numpy as np import mytorcha as mt print(mt.Tensor([1.0, 2.0]).dtype, mt.Tensor(np.array([1.0])).dtype, mt.Tensor([1, 2]).dtype) print(type(np.ones(3).sum())) ``` ```output float32 float64 int64 ```

Python floats become float32, like in PyTorch: half the memory and plenty of precision for training. NumPy arrays keep their dtype, so float64 stays float64 (the gradient checker needs that) and integer labels stay integers. The second line is the clue to a real bug from this rebuild. Read on.

gradcheck: the lie detector

How do we know a backward rule is right? We don't trust it, we measure it. Nudge one input by ±h and see how much the output moves:

```math df/dx ≈ ( f(x + h) − f(x − h) ) / 2h (central difference, h = 1e-6) ```

mytorcha.gradcheck.gradcheck(f, inputs) does this for every element of every input and compares the result with backward(). Watch it catch v1's log bug, re-created on purpose:

```python import numpy as np import mytorcha as mt from mytorcha.gradcheck import gradcheck, rand def bad_log(t): # v1's bug: 1/log(x) instead of 1/x a = t.data return mt.Tensor._make(np.log(a), (t,), lambda g: (g / np.log(a),), "bad_log") x = rand(3, positive=True) # float64 test tensor try: gradcheck(lambda: bad_log(x), [x]) except AssertionError as e: print("caught:", e) print(gradcheck(lambda: x.log(), [x])) ``` ```output caught: input 0: max |analytic - numeric| = 6.73 True ```

Every op, activation, loss and layer in MyTorcha passes a gradcheck in the test suite, and the standard ones are also compared against PyTorch.

A true story from this rebuild. The very first gradcheck of a.sum() failed, with an error of 0.09. The backward rule was fine. The problem was that arr.sum() in NumPy returns a numpy.float64 scalar, not an ndarray. The Tensor constructor only recognised arrays, so it treated the scalar like a Python float and down-cast it to float32. Finite differences with h = 10⁻⁶ can't survive float32 rounding, so the check "failed". The fix was one line: treat np.generic like np.ndarray. The lesson is bigger than the fix. Use float64 for gradient checks, and when a check fails, suspect the measurement as much as the maths.

Shape operations

All of these are differentiable. Their backward just routes the gradient back to where each number came from.

```python import numpy as np import mytorcha as mt t = mt.arange(12).astype(np.float32).reshape(3, 4) print(t.shape, t.T.shape, t.reshape(2, 6).shape, t.unsqueeze(0).shape, t[:, 1:3].shape) ``` ```output (3, 4) (4, 3) (2, 6) (1, 3, 4) (3, 2) ```
OperationBackward does…
+ - * / **, exp log sqrt abs clipmultiply by the local derivative (then un-broadcast)
a @ bg @ bᵀ and aᵀ @ g
sum, meancopy the gradient back to every summed element (÷N for the mean)
max, minsend the gradient only to the winning element (ties share it)
reshape, transpose / permute, swapaxes, squeeze, unsqueeze, flattenapply the inverse reshape or permutation to the gradient
t[idx] (slices, integer arrays)scatter the gradient back with np.add.at, so repeated indices add up. That's how Embedding learns.
concat, stack, pad, where, masked_fillsplit, crop or mask the gradient

Comparisons like t > 0 return boolean tensors with no gradient, which is handy for masks.

Try it

1. w has shape (1, 3) and is multiplied by a (5, 3) tensor of ones, then summed. What is w.grad?

[[5. 5. 5.]]. w was broadcast over 5 rows, so each entry collects 5 gradients of 1. The shape stays (1, 3), exactly the shape of w.

2. a = Tensor([1., 2., 3.], requires_grad=True); b = a * 2; b.sum().backward(). What are b.grad and a.grad?

b.grad = [1. 1. 1.] and a.grad = [2. 2. 2.]. MyTorcha keeps intermediate gradients so you can inspect them. Great for learning, a little memory-hungry.

3. x = Tensor([[1., 5.], [7., 2.]], requires_grad=True); x.max(axis=1).sum().backward(). What is x.grad?

[[0. 1.] [1. 0.]]. Only the winner of each row (5 and 7) influenced the output, so only they get gradient. This is exactly max-pooling's backward in chapter 5.

4. You train for 100 steps without ever calling zero_grad(). What happens?

Each step uses the sum of all past gradients, so the updates get bigger and point at where the loss used to slope. Training usually blows up, or wanders off and never settles. Zero your grads.
